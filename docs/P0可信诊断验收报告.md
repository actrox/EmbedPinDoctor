# P0 可信诊断闭环验收报告

## 目标

让 EmbedPinDoctor 的诊断结果具备明确的数据契约、可追溯来源、全局约束分配、电气安全规则和可重复回归验证。机器校验与人工签字必须分开，程序不得把未经工程师复核的数据标记为已验证。

## 完成项

| 编号 | 能力 | 状态 | 验收方式 |
| --- | --- | --- | --- |
| P0-01 | 芯片 JSON Schema v1 | 完成 | 缺字段、错误类型、重复引脚会被拒绝 |
| P0-02 | 模块 JSON Schema v1 | 完成 | 强制信号方向、电压、来源和接口需求 |
| P0-03 | 数据来源与可信度 | 完成 | 三款芯片记录官方手册、章节、机器检查日期与人工签字状态 |
| P0-04 | 数据审计工具 | 完成 | `python -m quality.data_audit` 返回错误和待人工审核项 |
| P0-05 | 数据包导入安全 | 完成 | 整包先校验后写入，拒绝部分覆盖和文件名/id 不一致 |
| P0-06 | 全局约束分配 | 完成 | 有界回溯最大化已分配信号，再最大化总评分；结果确定性 |
| P0-07 | 输入/输出能力检查 | 完成 | 输出信号不会分配到 ESP32 输入专用脚 |
| P0-08 | 关键电气规则 | 完成 | 检查输入过压、GPIO 过流、5V 容忍和开漏能力 |
| P0-09 | 风险置信度评分 | 完成 | 风险权重同时考虑严重级别与置信度 |
| P0-10 | 可信诊断回归测试 | 完成 | 正反例、边界值、回溯案例和确定性案例纳入测试集 |

## 数据审核状态

- STM32F103C8T6：官方来源已记录，机器校验通过，待硬件工程师签字。
- ESP32-WROOM-32：官方来源已记录，输入专用脚及启动脚约束已补充，待硬件工程师签字。
- RP2040：官方来源已记录，机器校验通过，待硬件工程师签字。

在人工签字前，诊断结果固定包含 `data_unverified` 提示。只有同时填写 `verified=true`、`data_status=verified`、`verified_at` 和 `verified_by`，数据才能进入已验证状态。

## 运行验收

```bash
python -m quality.data_audit
python run_tests.py
```

P0 完成的含义是“可信机制和安全门禁已经落地”，不代表工具可以替代数据手册、原理图审查或实物电气测试。
