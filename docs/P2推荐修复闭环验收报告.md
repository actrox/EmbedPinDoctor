# P2 推荐与修复闭环验收报告

## 目标

把单一自动分配升级为可解释、可锁定、可比较的多方案决策流程，并在引脚级规则之外检查共享总线和定时器资源冲突。

## 完成项

| 编号 | 能力 | 状态 | 验收方式 |
| --- | --- | --- | --- |
| P2-01 | 引脚锁定 | 完成 | 以 `module_id:module_pin` 锁定物理引脚，锁定是强约束 |
| P2-02 | 锁定冲突诊断 | 完成 | 不兼容或被占用时返回 `locked_pin_conflict`，不静默改脚 |
| P2-03 | 最小变更策略 | 完成 | 在不减少可分配信号的前提下优先保留现有接线 |
| P2-04 | 多方案枚举 | 完成 | 最多返回 5 套真实、互不重复且完整度不下降的方案 |
| P2-05 | 方案差异 | 完成 | 每套备选方案记录变更信号、原引脚和新引脚 |
| P2-06 | 推荐理由 | 完成 | 每路分配解释功能匹配、风险规避、锁定或保持原因 |
| P2-07 | I2C 地址检查 | 完成 | 同总线同地址设备报告错误 |
| P2-08 | SPI 共享检查 | 完成 | 提示模式切换和最慢设备安全频率 |
| P2-09 | UART 流控检查 | 完成 | 声明硬件流控但缺少 CTS/RTS 时报告警告 |
| P2-10 | PWM 定时器检查 | 完成 | 同一定时器不同基频报告错误 |
| P2-11 | 工作台方案卡 | 完成 | 展示评分和变化数量，可采用备选方案 |
| P2-12 | 工作台锁定控件 | 完成 | 可锁定表格中的当前引脚并重新求解 |

## 求解目标顺序

1. 最大化成功分配的信号数量。
2. 在“最小变更”策略下最大化保留的现有接线数量。
3. 最大化引脚质量评分并避开启动、调试等风险脚。

因此，保持旧接线不会以产生未分配信号或违反强约束为代价。

## 验收

```bash
python tests/p2_recommendation_test.py
python run_tests.py
```

专项测试覆盖有效锁定、无效锁定、最小变更、三套不同方案、选择理由，以及 I2C、SPI、UART 和 PWM 五类资源问题。
